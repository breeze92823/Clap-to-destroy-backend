# Clap to Destroy — BACKEND (game server)

Frontend (3D client) lives at `../Clap-to-distroy`. Colyseus + Mongo, ported from the Bowling Roll / Kayak-and-surf servers and reshaped for Clap to Destroy's save. The frontend's `net.js` uses all of this (the server's doc is the only save).

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`, client calls `joinOrCreate("world", { userId, username, pfp })`). Client-authoritative: the server only bounds/sanitises saves (`src/sanitize.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable; guests (`guest-` ids) are never saved. `/health` for Legion; `/monitor` and the playground are dev-only.
- Messages client -> server: `saveProgress` (the whole snapshot, debounced client-side), `identify` (`{ userId, username, pfp }` after a sign-in/out mid-session). Server -> client (private): `progress` (the saved doc, sanitized), `noProgress` (new account, guest, or no database: the client keeps its fresh state and saves it), `serverError` (the save could not be read: saving stays off so it is never overwritten). Saves are ignored until the session's load has answered (`loaded`). A second live session on the same account is evicted. Roster (`PlayerState`): `username`, `signedIn`, `pfp` (http(s) only, max `PFP_MAX_LEN`) plus presence.
- Saved progress shape (`PlayerDoc` = the client's `createGame` state `S` in `src/game.js`): `skill`, `wins`, `candy`, `rebirths`, `autoRebirth`, `level`, `pumpkins`, `playTime` (s), owned/equipped pairs `owned`/`equipped` (gauntlet ids) and `trails`/`trail` ("" = none; the equipped id must be owned), `pets[] { id, kind, equipped, locked }` (unique integer ids, equipped capped at `petSlots`), `nextPetId`, `petSlots`, `petsSeen[]`, `autoDelete`, `eggs { key: n }`, `boosts { type: n }`, `boostUntil { type: ms }`, `perm { skill, wins }` (permanent boosts), `autoClapOwned`, `giftLeft` (s), `lastSeen`. Unknown fields are dropped.
- Daily Reward (`src/daily.ts`, `DAILY_DAYS` = the client's `DAILY.days.length`): server-authoritative on the server's UTC clock. Doc fields `dailyDay`, `dailyLast`, `dailyClaimed[]`, written only by the server, never by `saveProgress`. After the load the client gets `daily` { unlocked, claimed, nextAt, serverTime }; `claimDaily` { day } answers `dailyResult`; `dailyRefresh` re-rolls after midnight.
- Leaderboards (`src/leaderboard.ts`): top `LEADERBOARD_SIZE` saved players by each of `LEADERBOARD_STATS` (`level`, `playTime`, `skill`, `wins` = the plaza's Top Level / Time Played / Top Skills / Wins), one process-wide cache refreshed at most every `LEADERBOARD_EVERY_MS`; own rank = countDocuments(stat > theirs) + 1 (null for guests / no score). Server -> client `leaderboard` { boards: { stat: [{ name, value }] }, ranks: { stat: n | null } }, sent after each load and every `LEADERBOARD_EVERY_MS`. `connectDb` creates a descending index per stat.- Presence (`src/presence.ts`): relayed through the roster as sent, only bounded. Roster fields `x`/`y`/`z` (feet, m, |v| <= `POSE_BOUNDS.xy`), `yaw` (wrapped to -PI..PI), `speed`, `grounded`, `gauntlet`/`trail` (ids matching `ID_PATTERN`, "" = none), `pets` ("kind,kind", at most `PRESENCE_PETS_MAX`), `world`, `avatar` (Bloxity look JSON, at most `AVATAR_MAX_LEN`). Messages `pose` { x, y, z, yaw, speed, grounded }, `loadout` { gauntlet, trail, pets: [{ kind }], world }, `setAvatar` { avatar }; join options may carry them too.
- Clap effects: client `fx` { kind: `clap` | `wave` | `train`, x, y, z, yaw, range? } (`sanitizeFx`: bounded, per-kind rate limit `FX_MIN_GAP_MS`, `range` <= `FX_RANGE_MAX`) is broadcast to everyone else as `fx` { id (sessionId), ...same }. Not stored.
- Removed with Bowling Roll: the race roster (`race`, `racing`, `distance`), the spin wheel, boats/engines/partners/gems/energy/bestDistance.
- `src/constants.ts` bounds must cover the client's `src/config.js`. A contract change goes in both projects.
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev), sending `roomSize` = `ROOM_MAX_CLIENTS` read from `src/constants.ts` (keep it 2-100). Needs repo var/secret `LEGION_GAME_ID` (= `clap-to-distroy`, the frontend `GAME_SLUG`) and secret `LEGION_DEPLOY_TOKEN`.
